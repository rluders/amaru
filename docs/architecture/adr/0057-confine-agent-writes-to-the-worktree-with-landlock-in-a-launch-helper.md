# 0057. Confine agent writes to the worktree with Landlock, applied by a launch helper, and refuse the Step when it cannot be enforced

## Context
- **The gap.** FEAT-ENV-010 (#154) requires that "agents write only inside" the Work Item's worktree. [ADR-0056](0056-adapt-the-prototype-git-worktree-provider-into-the-worker-providers.md) item 7 assigns that to "the Worker's path and process confinement ([ADR-0053](0053-adapt-the-prototype-process-and-path-code-into-the-worker-os-layer.md))". **That confinement does not exist.** ADR-0053 moved argv-only start, an allow-listed environment, an explicit directory and process-tree termination; it moved no write restriction, and its Follow-up says a confinement beyond the process group needs a new ADR because none exists. `internal/worker/osproc` today starts any program with any permissions of the Worker's user. The worktree package only decides the directory.
- **Why a directory is not isolation.** An agent started with `Dir` set to the worktree can still write to any path its user can (the Project checkout, `~/.ssh`, other worktrees). Vendor flags do not close this: the feature catalog records that the prototype's Codex and OpenCode providers ignored `WorkspaceWrite` (FEAT-POL-006, evidence column). FEAT-POL-006 requires a Step to be **refused** when the requested restriction cannot be enforced.
- **What Linux offers (verified 2026-10-28, [kernel Landlock user guide](https://docs.kernel.org/userspace-api/landlock.html)).**
  - Landlock is an unprivileged, path-based sandbox. A ruleset restricts "the thread enforcing it, and its future children", so a descendant cannot escape by `setsid` or by changing process group (the limit ADR-0053 documents for the kill mechanism does not apply to a filesystem rule).
  - Unprivileged use requires `no_new_privs`. The ABI version is read at runtime; an application must choose per ABI which rights it handles. Rights added after ABI 1 include `REFER` (ABI 2), `TRUNCATE` (ABI 3), `IOCTL_DEV` and others. The guide recommends best-effort degrading; this ADR rejects that for the write guarantee (item 3).
  - A ruleset is applied to the calling thread. Go runs goroutines on several OS threads, so restricting the Worker itself would restrict a thread unpredictably, or, with the whole-process flag the guide documents for ABI 8, would restrict the Worker for good. The restriction must therefore be applied in the child, before the agent program is executed.
  - On the development machine (Fedora 43, kernel 7.2.11) `landlock` is in the active LSM list and the ABI query returns 10 (`/sys/kernel/security/lsm`, a raw `landlock_create_ruleset` version call). That is one host, not a statement about users' kernels.
- **Library.** `github.com/landlock-lsm/go-landlock` v0.11.0 (MIT, published 2026-10-23 per pkg.go.dev) wraps the syscalls (`RWDirs`, `RODirs`, `Config.BestEffort`, `Restrict`). It is an additional module dependency (and brings `golang.org/x/sys`, which ADR-0053 already named as the Windows upgrade dependency). Verified: the package index and license on pkg.go.dev and the repository `LICENSE` (MIT). **Unverified:** its transitive requirements and the exact behavior of a rule on a path that does not exist; both are checked when the dependency is added.
- **Not covered by Landlock's filesystem rights:** reads, network (separate rights, ABI 4 and later, and Amaru's egress consent is #168), signals and `ptrace`. This ADR is about writes.
- **Unverified:** that every Provider's CLI runs when its only writable roots are the worktree plus declared state directories (item 4); this is the main risk and is checked per Provider (WP-M3-05) with recorded runs, not assumed.

## Decision
1. **Mechanism: Landlock, on Linux.** The Worker confines an agent process with a Landlock ruleset that handles all filesystem write rights (create, write, truncate, remove, rename and link into other directories, device ioctl). Reads and execution stay allowed everywhere the user can read, so the agent's toolchain keeps working. Network and signals are out of scope here.
2. **Launch helper.** The ruleset is applied by a short-lived helper, not by the Worker process. The Worker starts itself again in a `confine-exec` mode with the writable roots in its arguments; the helper sets `no_new_privs`, applies the ruleset to itself and then `exec`s the agent program, so the agent inherits it and nothing else is restricted. The helper is a subcommand of the Worker binary, not a second binary, and uses no shell. The process port stays the one in `internal/ports/process.go`, extended by a `Confinement` value on `ProcSpec` (item 5); the OS layer implements it.
3. **Fail closed.** A Step that requests write confinement is **refused**, with a typed reason (the POL-006 refusal), when the OS has no enforcing mechanism or the kernel's Landlock ABI is below the version that covers truncate and rename across directories (ABI 3; the minimum is confirmed when the dependency is added). There is **no best-effort degradation** for this guarantee and no silent run unconfined. Windows and macOS have no mechanism in this ADR, so a confinement-requiring Step is refused there; this is consistent with the owner's decision that both are out of scope for M3.
4. **Writable roots.** Exactly one root is always writable: the worktree directory from `worktree.Repo.Dir` (ADR-0056). A Provider may declare additional writable roots it needs (its own state or cache directory, a per-Step temporary directory); each is validated like a worktree path (absolute, no `..`, symlinks resolved, not the Project checkout and not a parent of it) and shown to the approver as part of the Step's requested permissions. The Project checkout, other worktrees, the home directory and `~/.ssh` are never writable roots. Anything the Provider declares beyond the worktree is a Policy matter (ADR-0055), not a default.
5. **No unconfined zero value.** `ProcSpec.Confinement` is a pointer: `nil` is an explicit "not confined", allowed only for a Step that did not request a write restriction (for example `git` run by the Worker itself). The agent execution path passes a non-nil value or does not start. The coordinator never infers confinement from a vendor flag.
6. **Evidence.** The Worker reports in the Step's result whether confinement was enforced and with what roots (a fact, not a vendor claim). It records a refusal as an Event with the reason. The Linux validation record states the kernel and Landlock ABI of the host it ran on.
7. **Tests.** Real, not mocked, on Linux: a child started through the helper (a) writes inside the root, (b) fails with a permission error writing outside it, via a symlink inside the root pointing out, and by renaming or hard-linking an outside file in, (c) a grandchild that calls `setsid` is still confined, (d) the helper refuses when asked for a relative root or one that overlaps the checkout. A test that needs a kernel without Landlock is not possible on the CI hosts, so the refusal path is tested with a fake probe and the real-kernel path is skipped, with the skip logged, where Landlock is absent. macOS and Windows get the refusal test only.
8. **Dependency.** Add `github.com/landlock-lsm/go-landlock` pinned to v0.11.0 (MIT), used only in the helper's Linux file, behind a build tag. The alternative of calling the three syscalls through `golang.org/x/sys/unix` directly (no go-landlock) is acceptable to the implementer if the owner prefers one dependency over two; item 8 asks the owner to choose.
9. **Scope of #154.** After this ADR is accepted and implemented, #154's criterion "agents write only inside it" is met at the level the tests show (Linux, unit and integration). It is **not real-validated against any vendor agent CLI**; that is recorded per Provider in WP-M3-05.

## Consequences
- **Easier:** the guarantee no longer depends on each vendor's flags; a Step that cannot be confined never runs. The same mechanism serves POL-006 for every Provider.
- **Harder:** one more dependency, one more mode in the Worker binary, and a startup cost per confined process (one extra `exec`). Providers must list the state directories their CLI writes, and some will need work to run confined.
- **Security:** reads and network stay open, so a confined agent can still read secrets the user can read and exfiltrate over the network. This ADR does not claim otherwise; read confinement and egress are separate decisions (#168 covers egress consent). Nothing here weakens the security baseline.
- **Revisit when:** a supported Provider cannot run under the writable roots it can reasonably declare; Windows or macOS leave "out of scope"; a stronger boundary (namespaces, containers) is wanted for untrusted Plugins or the cloud tier.

## Alternatives considered
- **Vendor flags only (`WorkspaceWrite` and similar):** the catalog records that two prototype providers ignored them; not enforced by Amaru.
- **Validate paths in Amaru code only:** constrains what Amaru writes, not what a child process writes.
- **Apply Landlock in the Worker process:** per-thread in Go, unpredictable, and it would confine the Worker itself.
- **bubblewrap or another external sandbox binary:** needs user namespaces, which some distributions disable for unprivileged users, and an extra install in the compact distribution. The tool exists on the development host; that is not the compact install.
- **Containers or cgroups:** stronger, but not available in the compact install on all OSes and an infrastructure decision (AGENTS.md rule 6); ADR-0053 already declined them for the kill mechanism.
- **seccomp filters:** syscall-based, not path-based; cannot express "write only here".
- **Do not confine in M3 and record the criterion as unmet:** honest and cheap, but leaves a P0 feature without its acceptance criterion and leaves POL-006 with nothing to refuse on.
