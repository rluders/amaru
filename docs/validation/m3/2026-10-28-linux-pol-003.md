## What the Linux run covers (acceptance: "every Approval, Grant and Policy change is an Event with actor and reason")
- **Grant:** creating and revoking a Grant (directly on the store and through `Coordinator.CreateGrant` / `RevokeGrant`) each write one event with kind, actor (the human's id), reason (the revoke reason), target and Project, numbered from 1 without gaps. A lapse and an expiry produce events with the Platform as actor and a reason code.
- **No event without a change, no change without an event:** a duplicate create, an invalid Grant, a stale update, an in-place edit and a refused revoke (wrong role, no reason, already revoked) leave no event. In PostgreSQL a rolled-back write gives its number back.
- **Replay:** the log is read from the start or from any `Seq`, in pages, in order.
- **PostgreSQL:** `audit_events` refuses update and delete; `seq` stays gapless with 12 concurrent writers.

Evidence level: integration-tested on Linux (fakes, plus PostgreSQL for the stores). No real agent, provider or forge ran, so nothing here is real-validated.
