## Acceptance
| Criterion | Evidence level | What shows it |
|---|---|---|
| One worktree per Work Item | **integration-tested** | Two keys give two directories under the configured root, each on its own branch started from the fetched base with no upstream; an edit in one is not in the other; the user's checkout (files, head, status) is unchanged (`TestPrepareCreatesOneWorktreePerWorkItemOutsideTheCheckout`). Prepare is idempotent and rebuilds a lost worktree on its existing branch. |
| Agents write only inside it | **not implemented** | The provider decides the directory and `Dir` gives the one root to hand to the agent. Nothing here stops a process from writing elsewhere: path and process confinement in the Worker OS layer (ADR-0053) has no code in the repository yet. A git worktree is not a sandbox. |
| Base refresh merges, never rebases or force-pushes | **integration-tested** | The nine ported `Sync` behaviors run against real git and a local bare remote: merge of a moved base, behind without merging, up to date, conflict abort with the file list, dirty refusal, adoption of remote commits, divergence, pushing local commits, finishing an interrupted merge, undoing the merge on a lost push race. `TestNoOperationRebasesOrForcePushes` checks the recorded git arguments of a full lifecycle: no rebase or pull, no push with a force flag or `+` refspec, no `reset` without `--keep`. |

Also covered: `Remove` refuses a worktree with a modified file, an untracked file or an unpushed commit, and with `discard` reports the counts and the head; hooks of the repository do not run; invalid keys and branches are refused before git runs; the root may not lie inside the checkout.

Evidence level: integration-tested on Linux against real git. The tests run only where `git` is on the PATH and skip with a reason otherwise.
