## What the command matrix establishes

[IdempotencySuite and CommandAtomicitySuite](../../../services/platform/internal/coordinator/coordtest/idempotency.go) run against fake stores in `make check` and PostgreSQL in the focused/full database runs. They cover Submit, Cancel, DecideApproval, CreateGrant, RevokeGrant, TrustContent and RevokeTrust:

- Sequential and 16-way simultaneous delivery returns the original durable result and records one audit effect; cancellation appends its Events once.
- A new coordinator and fresh PostgreSQL adapters over retained data replay after a one-year clock advance, including creation of a Grant whose expiry passed. This recreates adapters, not the PostgreSQL server or operating system.
- Changed payload/target and actor reuse conflicts without returning an original result; invalid authority, missing/oversized/invalid UTF-8 keys and anonymous human cancellation are refused.
- Failure injected before the store write leaves no successful record; an injected lost acknowledgement after the real commit replays that result on retry.
- Failed Grant creation, stale Grant version and stale trust revocation roll back command records with the rejected mutation.
- Later Grant revocation or trust withdrawal/renewal cannot replace an old command outcome or cause its mutation to run again. Different command names can use the same key.

The fixture corpus covers required v1 body keys, cancellation shape and invalid keys; the generated SDK is current and fake-fetch tests send cancellation and Approval keys in their bodies. The [inventory](../../engineering/command-idempotency.md) records normalization, authorization, legacy anonymous cancellation handling and remaining HTTP boundaries.
