# Linux OBS-001 operational logging evidence

Date: 2026-11-12. Scope: [#170](https://github.com/rluders/amaru/issues/170), child of [#18](https://github.com/rluders/amaru/issues/18). Linux is the primary M3 target; other platforms remain best effort.

## Implemented boundary

`services/platform/internal/adapter/operational` emits newline-delimited JSON with timestamp, Instance and correlation identity, optional Project/Execution/Step identity, operation, outcome, safe cause and HTTP status. Identity comes from trusted command/Event context; HTTP generates a fresh correlation identity and ignores inbound correlation headers. Composition can read that identity with `IdentityFrom`, enrich it after resolving domain state, and pass it to `Write`. Idempotency keys are not correlation identities.

The logger uses the existing `domain.DefaultRedactor` and a snapshot of literal known secret values, longest first, before JSON escaping. Every string field is redacted, including identities. No new dependency or infrastructure, no predecessor source migration, no domain or Worker dependency on the adapter. Operational output never appends to domain/audit Events. A raw structured logger with arbitrary attributes was rejected because it permits accidental request/header/output capture.

HTTP wraps authentication and records only a fixed operation, outcome, generated identity and status: it never reads headers, URLs, bodies, response headers or Provider output for logging. Thus dynamically issued launch/session/CSRF credentials need no registration for HTTP capture. Panics emit a safe outcome and become `http.ErrAbortHandler`, preventing the standard server from dumping a raw panic value/stack. ResponseController unwrapping, flush and hijack are preserved for transport composition. The SDK auth fixture uses this wrapper and writes JSON to stdout; only safe logger failures go to stderr.

## Verification

- `make check`: local Linux, exit 0; repository checks include the new adapter tests and SDK auth fixture. These are local results, not hosted CI.
- `cd services/platform && go test -race -count=1 ./internal/adapter/operational`: exit 0.
- Unit-tested: JSON parsing, all-field redaction, overlapping/quoted/newline secret values, built-in Provider token pattern, concurrent line serialization, missing context, short writes and safe sink errors.
- Integration-tested: actual coordinator Submit and Cancel against a fake store, fake Runner failure with injected secret, selected Instance/Project/Execution/Step correlation and useful redacted failure cause. This fixture explicitly emits completion records; it does not instrument all coordinator/Worker paths.
- Integration-tested on a real loopback HTTP server: native bearer issuance, launch-code exchange, cookie/CSRF session read and rejected hostile request. Captured JSON excludes dynamically issued credentials and unregistered query/header/body fixtures. No real Provider, paid API or specialized tool is required.

## Limits and delivery gates

#170 stays open until reviewed delivery acceptance and composition coverage. #18 still owns product HTTP/Project Event WebSocket serving and complete command/Worker instrumentation. The test-only auth fixture is the only executable composition changed here. HTTP diagnostics deliberately omit route/method/payload details; correlate selected command records through the generated request identity instead. No running product server or full stdout/stderr/Provider-output capture is claimed.

Known Provider values must be supplied when constructing the logger; replace it when that set changes. Unknown unlabelled secrets and encoded variants are not guaranteed to match pattern scanning. Never send raw auth errors, requests or Provider output to `Record.Cause`. A writer failure returns a generic safe error; HTTP invokes the required safe error callback. Logging failure does not retry or undo a committed command. Partial sink writes can leave a partial final line; log shipping, rotation, durability and recovery are outside this feature slice. Cross-platform runtime behavior and real Provider diagnostics were not validated.
