## Evidence and architecture review

**Unit-tested:** resync classification and JSON shape; fake store cases for Project/Execution order, exclusive pagination, deterministic redelivery, empty/current reads, filtering and Project isolation, invalid queries, future cursors, fake-clock expiry at compact/server windows, failed state changes and concurrent writers. Event occurrence times are deliberately old/reversed to distinguish them from Platform recording order/time.

**Integration-tested:** the same contract against PostgreSQL, plus committed-only visibility while a journal transaction remains open, replay through a new store instance, an injected journal constraint failure that rolls back state and both logs, successful retry without a cursor gap, and an upgrade from the actual prior migration set preserving historical Execution Events without inventing their Project order. The final full run also passed the retained-suffix/missing-history reader case and existing store/migration regression tests.

Architecture-review verdict: **sound within the approved core scope**. Platform storage owns counters and Events; Worker timestamps assign neither order nor replay eligibility. Pure domain types/policy and the storage port import no network/OS adapters. The existing PostgreSQL transaction and migration runner are reused; no dependency or infrastructure is added. Sorting by timestamps or using a nontransactional SQL sequence would allow ambiguous order or a resume cursor ahead of an uncommitted event; the existing Execution counter alone cannot order multiple Executions in one Project. A crash/failed write rolls the Project index back with the transition. Repeatable-read ties page contents, history floor and high-water mark to one committed snapshot. Project counter locks serialize writers within a Project, which is the intended correctness tradeoff; separate Projects use independent counters. No new human architecture decision or accepted ADR is introduced.

**Not validated:** native macOS/Windows, real Providers, public HTTP/WebSocket reconnect, public typed Event envelope mapping and API authorization/Cloud tenant isolation. This indexes existing Execution Events only; Work/Workflow/Agent change producers (#219) and combined audit integration (#188) remain open. Replay-window checks do not physically delete history; cleanup remains ART-003. Reloading client state and applying subsequent replay requires idempotent/revision-aware client composition. These limits are explicit in the [core behavior documentation](../../engineering/event-stream.md); this record does not establish #18 or M3 exit acceptance.
