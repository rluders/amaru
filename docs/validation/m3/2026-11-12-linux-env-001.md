## Architecture review and limitations

Verdict: **sound**. This adds test coverage and shares an existing test transport helper; it changes no production code, schemas, dependencies, runtime wiring or infrastructure. The coordinator remains authoritative; the Worker receives assignments and reports through ports. No migration from Weave is performed. Reusing only the coordinator message suite would leave actual Runner cancellation and lifecycle parity unchecked; the focused Worker cases cover those gaps without introducing another transport implementation.

The serialization stand-in rebuilds messages as JSON over in-process channels. It is not a separate-process Worker, WebSocket/Protobuf transport, enrollment, TLS or network validation. Restart here replaces instances over an in-memory store; durable process-kill evidence is recorded separately in [EXE-002](2026-11-12-linux-exe-002.md). No real OS process-tree execution, remote service or full Platform executable is validated by these new cases. Native macOS and Windows were not run; best effort for M3 under the [owner decision](../../engineering/validation.md#scope-decision-product-owner-2026-11-12). Cross-vet is only an early compatibility check. M4 and security requirements are unchanged.

#145 stays open until review and merge into its designated integration branch; #15 still needs #157, #158 and integrated acceptance. No new human architecture decision is needed for this change.
