# Platform process resource owners

Owner: Platform (#18). These are concrete composition helpers under accepted [ADR-0068](../../../../docs/architecture/adr/0068-platform-process-readiness-and-bounded-shutdown.md), outside domain, Coordinator, ports and Worker execution logic.

`Storage` opens its own database/sql pool inside Start from a pgx stdlib connector, checks connectivity and publishes completion readiness. `Schema` runs the existing checksum-verified embedded migration runner under its existing advisory lock. Register each in its own stage of the single outer Lane, storage first. Constructors acquire no resources; create fresh owners for each process run. WaitReady may precede Start. Both initializers use the same absolute startup deadline supplied by composition; it bounds initialization, not healthy lifetime. The composition root must still implement the aggregate watchdog for all stages.

Dependents obtain the pool through `Storage.DB` after readiness. Start cancellation leaves the pool available through dependent joins. Reverse Stop joins schema/lock release and closes storage last. Storage Stop starts cleanup exactly once even when its cleanup context has already expired, waits only within that context, and returns failure if the budget is exhausted. Cleanup may continue after timeout if a driver ignores cancellation; the entrypoint must treat that as failure and exit, as ADR-0068 requires. Storage cleanup panics are contained without formatting their values. Raw driver, migration and Lane returned errors remain unsafe to print; use the existing safe lifecycle diagnostic boundary.

This is **partial implementation**, exercised with actual Lane and fake SQL connections in default tests, and PostgreSQL in the separately tagged tests. It creates no production entrypoint, configured connector, bundled PostgreSQL child owner, messaging/outbox, recovery/Worker composition, public admission, HTTP/discovery, or diagnostic consumer. It never stops an external database server, undoes migrations or deletes existing data. No new dependency or public configuration flag is introduced.

Driver panics can strand database/sql connection ownership or block a migration's deferred sql.Conn.Close before Lane sees the panic. Subprocess tests demonstrate failure without downstream admission under cancellation and a bounded shutdown budget; they do not establish graceful cleanup of a broken driver. Production composition still needs the independent startup watchdog and failure exit described by ADR-0068. The owner expects the pinned pgx connector, not arbitrary third-party drivers.

Validation is included in root `make check` through `platform-test`. From `services/platform`, focused checks are `go test -race -count=1 ./internal/platform` and, with `AMARU_TEST_PG` pointing to a disposable server whose role can create databases, `go test -race -count=1 -tags pg ./internal/platform`. These are resource/stage tests, not full product acceptance.
