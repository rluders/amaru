## Environment and evidence

Linux `7.2.11-100.fc43.x86_64`, amd64; Firefox `159.0.1`;
shell Go `1.26.0`, module-selected Go `1.27.0`.
`/proc/net/if_inet6` showed `::1` on `lo`. The browser test actually bound
`[::1]:0`; it did not substitute IPv4 or skip unavailable IPv6.

- **Unit-tested:** `TestIPv6HostOriginSession` initializes Auth with an IPv6
  loopback address and exercises native issuance, a rejected wrong-port launch
  followed by successful exchange, fixed redirect, safe cookie attributes,
  replay rejection, session read, mutation, WebSocket authorization and logout.
  Wrong/missing ports, unbracketed, wildcard, foreign, scoped and expanded IPv6
  Host forms are rejected at health/session/downstream routes. Missing, null,
  wrong-port, HTTPS, malformed, scoped, foreign and path-bearing Origins fail
  mutations/logout/upgrades. Missing session, missing/wrong CSRF and mixed
  credentials fail. Rejections dispatch zero downstream calls; positive controls
  dispatch exactly twice and the revoked cookie fails session read.
- **Real-validated:** the existing opt-in Firefox test now includes `::1`, with a
  real IPv6 TCP listener, isolated native browser profile and actual browser
  fetch/WebSocket operations. The browser receives the launch redirect and sends
  the Secure, HttpOnly session cookie over HTTP loopback; JavaScript cannot read
  the cookie. Missing CSRF fails, correct CSRF succeeds, an authenticated socket
  opens, logout closes it, and later session read returns 401. The full probe
  passed for localhost, 127.0.0.1 and ::1. Native code issuance is in-process via
  the actual Auth handler; the browser exchange and subsequent requests use the
  real listener. The downstream page/probe/WebSocket handshake are test fixtures,
  not product routes/Event transport. Browser diagnostics and credentials are
  discarded; temporary profiles are removed.

## Remaining gaps

No production bootstrap, simultaneous dual-stack listener publication, canonical
state directory/discovery startup, CLI `amaru open`, composed product/Event
transport or full M3 acceptance is established. The browser probe covers Firefox
on this Linux host only; Chromium, native macOS/Windows and their browser cookie
behavior remain **not validated**. The new negative cases use synthetic requests,
not hostile-page browser automation. No new PostgreSQL or real Provider run was
performed. Existing lifetime/expiry and other auth tests remain separate evidence.
#92 and #18 remain open; no new human security decision is required by this
coverage-only change.
